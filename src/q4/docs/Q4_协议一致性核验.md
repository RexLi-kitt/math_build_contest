# Q4 本地模拟器与官方协议的一致性核验

核验依据：B题附录 1、附录 2，以及附件 1、附件 2 的动作与计时说明。

| 项目 | 官方规则 | 本地实现 | 核验状态 |
|---|---|---|---|
| 目标数量与频道 | 10--16 个源，频道互异且在 1--20 | 生成 10--16 个互异频道源 | 已对齐 |
| 目标空间 | 半径 1800 m 圆域 | 按面积均匀抽样 (r=1800\sqrt U) | 已对齐 |
| 有效接收半径 | 1000--1500 m | 每源独立均匀抽样 | 已对齐 |
| 定向可见性 | 发射方向两侧各 90°，边界包含 | `abs(wrap(...))<=90` | 已对齐 |
| 示向度 | 真方位加 [-1°,1°] 固定地点误差，保留两位小数 | 频道—坐标哈希固定误差，`round(...,2)` | 已对齐 |
| `/measure` | 移动 + 必要切频 1 s + 检测 5 s | 同一动作内累计，成功后才更新当前频道 | 已对齐 |
| `/clear` | 移动 + 失败 3 s / 成功 5 s；不切频道 | 同一动作内累计，失败 3 s、成功 5 s，频道不变 | 已对齐 |
| 三种测量结果 | `direction / near / no_signal` | 同名字符串；`near` 无 `svd_deg` | 已对齐 |
| 清除结果 | `success / no_target_in_range` | 同名字符串，半径 20 m | 已对齐 |
| 请求幂等 | 同 ID 同内容不重复动作；同 ID 改内容冲突 | 本地 request_id 缓存并返回 409 标记 | 已对齐（本地 API 层） |
| 虚拟时间 | accepted=false 返回 0；accepted=true 累积 | 已实现 | 已对齐（本地 API 层） |
| HTTP+JSON 格式 | 端口、登录、HTTP 状态、字段严格校验 | 本地为 Python 直接调用，不模拟网络服务 | 未覆盖 |
| 现实时间窗口 | `/enter` 返回真实剩余时间，最长 20 分钟 | 仅提供 1200 s 占位字段，不模拟倒计时/网络超时 | 未覆盖 |
| 官方隐藏案例 | 官方随机生成机制不可读取 | 本地仅使用自定义随机分布 | 不可保证相同 |
| 官方日志加密上传 | 模拟器自动生成并上传 | 本地输出可读 JSON 调试日志 | 未覆盖 |

## 已执行的计时契约测试

附件给出的示例序列已在 `../tests/test_q4_protocol_contract.py` 验证：

1. `/enter` 后虚拟时间为 0；
2. `(0,0)→(300,400)` 对频道 1 检测，累计 105 s；
3. 原地切换至频道 2 检测，累计 111 s；
4. 移至 `(300,0)` 对频道 3 `/clear` 失败，累计 194 s，测向频道仍为 2；
5. 原地检测频道 2，累计 199 s；
6. 以相同 request_id 重发最后动作，虚拟时间不再推进。

## 结论

本地模拟器现在可作为**动作规则、时间账本、定向可见性和策略单元测试的等价替身**。但它不能代替官方 HTTP 服务，也不能证明与官方隐藏案例生成器完全相同。最终“效果一致”必须在已登录的官方问题4演练环境，用同一动作序列逐条比对响应字段、虚拟时间和原始日志后确认。
