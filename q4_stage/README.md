# 第四问定向源离线实验

## 最新推荐入口

路线优化已完成：运行 `python run_route28.py --cases 500 --jobs 8 --output results/new_route_run`。
28点方案在独立500局中全部清除，平均756.10秒/源，同批旧31点方案801.83秒/源，
降低5.70%；200局边界最小接收半径压力场景也全部清除。
详见 `路线优化结果.md`。下面保留原31点程序及历史基准说明。

本目录在第三问 J+ 的基础上加入定向干扰源，用同一批随机案例比较：

- `Q3_Jplus_direct`：直接沿用第三问的原点加七点环搜索；
- `Q4_full_clear_950_C2`：用边长 950 米的等边三角网格多方位搜索，覆盖期每个
  已发现频道补到 2 条有效方位。

定向源的有效覆盖范围为发射中轴两侧各 90 度。两种策略都不把 `no_signal`
直接解释为源不在检测点附近，避免把位于定向源背面的观测错误地当作距离排除证据。

运行：

```powershell
python q4_experiment.py --cases 30 --seed 20260912 --output results/run_30
```

结果目录包含逐案例表、汇总指标和第一局动作日志。该程序是离线策略筛选工具，不能替代官方模拟器演练或生成正式测试日志。

## 已完成验证

运行命令：

```powershell
python q4_experiment.py --cases 100 --seed 20260912 --output results/validation100_v4
```

初始 900 米网格保底方案在 100 个配对案例中的全清除率为 100%，平均每源耗时
903.11 秒。随后以全清除率不低于 95% 为约束，对网格间距与覆盖期方位数进行筛选。

1100 米快速网格在独立 300 局中全清除 298 局，平均每源耗时 600.04 秒，但发生
过一次真正漏检，因此不满足全清除硬约束。最终采用 950 米网格与 2 条有效方位：
网格边长小于 1000 米接收半径下界，能够给出多方位发现保证；相同300局在加入
下述定位兜底前平均每源耗时为792.16秒。

为满足全清除硬约束，最终程序增加了只在常规定位耗尽时启用的“示向走廊清除”
兜底。它以最后一次有效示向为中轴，在 0 至 1500 米范围按纵向 30 米、横向
20 米布置清除点。由角误差上界可知走廊半宽不超过 26.18 米，而点阵最大覆盖
空隙小于 20 米，因此至少一个清除点能够命中；该步骤不依赖定向源是否继续可见。
加入兜底后用同一随机种子重跑 300 局，全清除率为 100%，平均每源耗时为
792.61 秒，P95 为 1073.41 秒。

参数筛选可运行：

```powershell
python q4_optimize.py --cases 300 --min-success 1.0 --jobs 8 --output results/optimization
```

`q4_optimize.py` 默认最多使用 8 个 CPU 核心并行运行，进度每完成约 5% 才输出
一次。若电脑同时还要运行官方模拟器，可把 `--jobs` 调低到 4。

同一批 50 局基准中，单进程耗时 14.95 秒，8 进程耗时 3.17 秒，加速约 4.7 倍。
`q4_experiment.py` 也支持相同的 `--jobs` 参数。

性能分析显示，约 86% 的单进程时间花在主动选点：5 局调用约 9.15 万次预测圆，
其中最小包围圆与角度带裁剪占主要部分；路径重排约占 11%，环境响应和动作计时
不足 1%。因此虚拟任务时间很长并不会让程序按同样时长等待，真正瓶颈是大量重复
几何计算。

最终 300 局的虚拟时间构成为：平均每源 792.61 秒，其中搜索阶段移动 461.88 秒
（58.3%）、搜索后的定位移动 170.19 秒（21.5%）、检测 130.25 秒（16.4%）、
频道切换 25.16 秒（3.2%）、清除 5.13 秒（0.6%）。搜索阶段合计占 76.5%，
因此后续降低平均时间应优先缩短31点覆盖路线，其次减少定位阶段的专程移动。
