# D 模型官方模拟器演练说明

## 1. 准备

使用 Python 3.10 或更新版本，不需要安装第三方库。运行前在官方模拟器中完成登录，选择
“问题4演练测试”，启动一局并等待倒计时结束、接口显示就绪。参赛队号只通过命令行参数
传入，不写入源码；程序日志会把响应中的队号替换为 `TEAM_ID`。

以下命令均从仓库根目录执行。每次 `/enter` 到 `/exit` 会占用一局演练，因此三个步骤应
分别使用三局新演练，不能在正式测试中试探接口。

## 2. 第一步：原点通路测试

先启动一局新的问题4演练，然后执行：

```powershell
python -B src/q4/official_q4_probe.py --robot-id "你的参赛队号" --radii 0
```

应依次看到 `/enter`、原点 `/measure` 和 `/exit` 被接受。连接失败时检查模拟器登录状态、
演练倒计时、队号、端口与 `arena_id`。若模拟器端口不是2026，可追加：

```powershell
--base-url http://127.0.0.1:实际端口
```

## 3. 第二步：1800米边界探针

再启动一局新的问题4演练，执行：

```powershell
python -B src/q4/official_q4_probe.py --robot-id "你的参赛队号"
```

程序沿 x 轴依次请求半径1799、1800、1801、1885和1966米的测量，并记录每个响应的
`accepted`。这些半径覆盖了边界两侧以及D的B、C路线最大半径量级。

- 五个请求都被接受：可以进入完整D演练；
- 1801米以上任一请求被拒绝：停止运行当前D。B、C各有14个认证站超过1800米，跳过或
  投影会改变站点集合，必须重新设计并认证路线；
- 探针退出码为2：接口通路存在，但至少一个测量请求被明确拒绝；
- 探针退出码为1：连接、登录、测试状态或响应格式发生错误。

## 4. 第三步：完整D演练

边界探针通过后，启动第三局新的问题4演练：

```powershell
python -B src/q4/official_d_runner.py --robot-id "你的参赛队号" --verbose
```

运行器直接加载仓库正式 `src/q4/d_agent.py` 和仓库内B/C路线资产。正常结束时应检查：

1. `cleared_channels == detected_channels`；
2. 官方界面显示任务正常退出；
3. 日志 `final.status` 为 `completed`；
4. 日志中的 `selected_route`、`origin_discoveries`、`pruned_observations` 有值；
5. 所有动作响应的 `accepted` 均为 `true`。

本程序日志自动写入 `outputs/q4/official_runs/`，每次使用时间戳新建文件，不覆盖旧演练。
同时保留官方模拟器生成的 `.jlog`，两份日志共同用于复盘。

## 5. 建议的演练批次

接口探针通过后，至少运行3局完整D演练。每局记录源数、原点发现数、选择分支、发现数、
清除数、虚拟总时间、现实耗时、拒绝动作数和官方退出原因。验收底线为全部源清除、零请求
拒绝、零异常退出。若第一局出现拒绝或未清除，不继续消耗演练次数，先用程序日志与官方
`.jlog` 定位最后一个成功动作和首个异常动作。

## 6. 正式测试前检查

- 使用 `outputs/q4/results/d_robustness/manifest.json` 核对D代码和路线资产没有被临时修改；
- 确认问题编号为4、队号正确、端口与 `arena_id` 正确；
- 关闭其他可能访问同一接口的脚本；
- 不把通路测试或半径探针用于正式测试；
- 正式运行后立即保存程序日志和官方 `.jlog`。
