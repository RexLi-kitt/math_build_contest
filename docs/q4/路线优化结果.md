# 第四问路线优化结果

推荐运行 `run_route28.py`。新方案为990米等边三角网格向北平移半个行距
（约428.68米），保留所有与半径1800米目标圆相交的三角形顶点，再加入原点，
共28个停靠点。访问顺序由多起点最近邻初解、2-opt和单点Or-opt优化，采用开放路径，
不要求返回原点。检测和清除规则继承此前的全清除版本。

## 独立验证

筛选使用seed 20260922的100局；以下500局使用未参与筛选的seed 20260923。

| 指标 | 原31点最近邻 | 新28点开放路线 |
|---|---:|---:|
| 全清除案例 | 500/500 | 500/500 |
| 平均每源时间（秒） | 801.83 | 756.10 |
| 每源时间P95（秒） | 1079.18 | 996.11 |
| 搜索移动（秒/源） | 464.28 | 390.72 |
| 搜索后移动（秒/源） | 172.20 | 201.82 |

平均每源节省45.73秒，约5.70%。搜索移动减少73.56秒/源，但搜索后移动增加
29.63秒/源，因此不能把搜索阶段节省全部当作总收益。该比较使用同一批案例，
不可直接用旧300局的792.61秒与新500局作配对比较。

另用200局边界压力场景验证：每局16源，12个定向源，全部接收半径1000米；
源位于边界或1700至1800米边界带，定向源中轴朝外。两种策略均200/200全清除；
新方案平均702.78秒/源，旧方案781.12秒/源。

## 覆盖依据与范围

任意源位于某个网格三角形内，该三角形必与目标圆相交，因此其三个顶点都被保留。
源到每个顶点的距离不超过990米，小于1000米接收半径下界；三个顶点的凸包包含源，
故它们不可能全在任意发射方向的严格背半平面，至少一个顶点可收到信号。
原点另行保留。这是发现阶段的几何充分条件。

还检查了圆边界720个点与圆内10000个随机点的近邻检测方位，最大空角约150.18度，
均小于180度。这个离散检查是实现核对，不替代上述连续几何论证。
发现后的角度带定位和走廊清除兜底保持原规则。报告中的100%为已运行案例全清除，
不能代替官方模拟器测试；本轮未调用官方正式测试。

## 未采用方案

- 31点仅做开放路线优化：100局移动略减，但检测增加，总平均时间793.65秒，
  高于同批旧方案786.26秒，因此未采用。
- 950米原网格仅按相交三角形裁剪：仍为31点，未删掉任何点。
- 平移28点但仍用最近邻：100局830.27秒/源，明显慢于优化顺序743.93秒/源。
- 平移28点后逐停靠点重排：100局745.63秒/源，没有优于固定优化顺序。

本轮没有改动顺路清除的250米阈值，避免将路线与清除调度效果混在一起。
本方案是在本轮已测候选中选出的改进，不是全局最优解证明。

## 运行

```powershell
python src/q4/run_route28.py --cases 500 --seed 20260923 --jobs 8 --output outputs/q4/results/new_route_run
```

默认配对比较旧方案和新方案。只运行新方案时追加 `--strategies ShiftB`。
所有时间表以各局总虚拟时间除以源数再取均值；本次全部清除，源数与清除数相同。
