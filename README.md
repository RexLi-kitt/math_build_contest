数学建模比赛协作仓库

本仓库用于三人团队共享题目、建模方案、代码和结果。论文由论文手在本地编写，所需材料统一从仓库获取。

文件放在哪里

比赛题目：分为 A题、B题、C题三个文件夹，分别保存题目和原始数据附件，供全队选题和查阅。原始文件保持不变，处理后的数据另存到对应小问的 src 目录。

docs：保存题目任务图和各小问方案卡，方案卡说明思路、假设、方法和预期结果。下设“审题报告”文件夹，集中保存对题意、任务要求、数据条件和关键难点的分析。选题前的报告可按“A题_审题报告”“B题_审题报告”“C题_审题报告”命名，使用 Markdown 或 Word 均可。

src：按 q1、q2 等小问保存代码、初始结果和计算过程。运行代码需要的辅助数据一并保存，并说明运行方法。

outputs：按小问保存已核对、可供论文手使用的图表、结果数据、关键代码和支撑材料。更新结果时同步更新文件说明，写清用途和对应版本。

ai-log：记录 AI 使用日期、使用者、工具或模型、用途以及输入输出摘要，供比赛材料整理时查阅。

杂项文件夹：初始留空，比赛过程中按需使用。

桌面数模资料已按上述框架归位，完整位置与版本说明见 [2026-09-15 归档记录](docs/归档记录/2026-09-15/README.md)。第三、四问实验在对应的 `src/q3/实验`、`src/q4/实验`；与已有内容不同的桌面版保存在对应目录的“历史版本”下。提交论文在 `paper/最终提交`，提交支撑包在 `支撑材料/提交原包`，官方工具在 `比赛题目/B题/官方工具`。

.github：保存自动化配置。main 更新后，自动合并到“李培煜的分支”，也可手动触发。目标分支尚未发布时会从 main 创建，合并冲突时停止并提示。

requirements.txt：记录运行代码需要的 Python 依赖，新增依赖时及时补充。

.gitignore：过滤缓存、虚拟环境、编辑器配置和临时文件。

LICENSE：保存项目许可证。

协作约定

开始工作前先同步最新内容，在自己的分支上修改。完成一部分工作后提交并推送，通过 PR 申请合并到 main，由负责人检查后合并。

远端分支更新后，本地仍需拉取更新。遇到冲突先与相关队友沟通，不直接覆盖他人的改动。

审题结论或求解方案变化后及时更新 docs。src 中保留工作过程，确认可用的成果放入 outputs，并告知论文手。分工、进度和遇到的问题及时在队内沟通。

A题、B题、C题是三个备选赛题；q1、q2 等表示选定赛题中的各个小问。
