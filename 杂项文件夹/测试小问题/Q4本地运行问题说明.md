# Q4 本地运行问题说明

## 现状

执行以下全量测试：

```powershell
python tools/run_all.py --tier all
```

共 67 个入口，通过 61 个，失败 6 个。Q1 至 Q4 的主链路均正常；失败项全部位于 Q4 的补充验证链路。

## 问题一：依赖了个人电脑上的硬编码目录

下列 Q4 脚本依赖：

```text
C:\Users\李\Desktop\Q4保底基线
```

但该目录在当前电脑上不存在，因此找不到：

```text
B模型\cert_route_agent.py
```

受影响入口：

- Q4-自检-C+门控代理
- Q4-C+门控筛选（5局）
- Q4-C+独立配对验证（4+2）
- Q4-动态顺序筛选（4+2）

同时，`Q4-自检-动态顺序代理` 因未能加载这套外部模型而出现：

```text
ModuleNotFoundError: No module named 'baseline_core'
```

## 问题二：配对汇总脚本的结果目录错误

`src/q4/route_report.py` 读取：

```text
src/outputs/q4/results/route_holdout500/case_results.csv
```

但项目的正式结果目录位于仓库根目录下：

```text
outputs/q4/results
```

当前也没有 `route_holdout500` 这份产物，因此 `Q4-配对效应汇总` 失败。

## 建议处理

1. 将 Q4 的 B/C 模型、`cert_route_agent.py` 和 `baseline_core.py` 等必要依赖提交到仓库；或把脚本改为使用仓库内的相对路径，避免依赖个人桌面目录。
2. 修正 `route_report.py` 的输入路径，统一读取根目录 `outputs/q4/results` 下的实际产物。
3. 若配对效应汇总必须使用 `route_holdout500`，请补充生成该目录及其 `case_results.csv` 的入口，或把汇总脚本改为对应现有结果目录。

## 结论

这是 Q4 脚本的可移植性和产物路径配置问题，并非核心算法或主链路运行失败。
